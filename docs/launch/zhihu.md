# 知乎：规则、写法与自写提纲

知乎不是"来试用"的渠道。这里的读者大多不会自托管，放 GitHub 链接的转化率本来就低，风险却不低。它真正能给你的是三样：方法论信誉、中文搜索的品牌锚点、以及少数愿意折腾的研究生和实验室。

所以知乎的目标是**把一个问题讲透**，不是发一篇项目介绍。

配套文件：可发布的草稿在 [`zhihu-draft.md`](zhihu-draft.md)（LLM 起草，发布时必须勾选 AI 声明）；本文给的是规则边界和一份**自写提纲**——照它用你自己的话写，就不用勾声明，也不会吃降权。

---

## 1. 三条硬规则

### 1.1 用了 AI 就必须声明（和 HN 正好相反）

Hacker News 是完全禁止 LLM 生成（连润色都不行）。知乎允许，但必须走平台提供的标识：

- 法律层面：《人工智能生成合成内容标识办法》2025-09-01 施行，第十条——「用户使用网络信息内容传播服务发布生成合成内容的，应当主动声明并使用服务提供者提供的标识功能进行标识。」<https://www.gov.cn/zhengce/zhengceku/202503/content_7014286.htm>
- 平台层面：知乎编辑器底部有「创作声明」，其中一项是「**包含 AI 辅助创作**」。
- 后果：政府网的政策解读引述平台负责人——「此前，平台的社区治理规则已经要求，用户发布使用 AI 技术进行辅助创作的内容，应主动添加『包含AI辅助创作』创作声明。而如果不主动添加，被平台检测到使用 AI 创作，则会被打上标识、**排序置后**或者『折叠』乃至删除封号。」<https://www.gov.cn/zhengce/202503/content_7014404.htm>

**「排序置后」是关键**。你就是去要曝光的，被降权等于白写。所以最划算的路径是自己写；用了 AI 就老实勾选。

检测能力目前很弱——南都实测知乎 24 小时内没有识别出未声明的 AI 内容（<https://view.inews.qq.com/a/20250917A03AOU00>）。但规则和处罚都写在明面上，不值得赌。

一个法律上的边界，供判断用：起草相关解读的律师说，《标识办法》没有明确界定"AI 辅助"和"AI 生成"，如果核心创意和整合是你自己做的，法律上并未强制标注；但"严格来说，只要使用了 AI，都应该进行标识"，未标识一旦被识别"很可能会…导致内容或账号被限流"（<https://www.36kr.com/p/3473297183955589>）。

### 1.2 链接：区分「参考资料」和「导流入口」

《知乎机构号使用规范（试行）》列举的恶意营销包括「多次发布包含联系方式、推广链接等导流信息的低质内容」「相同的回答多次重复发布在不同的问题下」「在较短时间内通过私信频繁邀请站内用户参加机构活动或发送产品推广内容」，处罚从禁言 1 天到永久封禁。<https://www.zhihu.com/term/institution-usage>

判断一条链接安不安全，问两句：

1. **删掉它，正文还成立吗？** 成立，就说明它不是必要信息。
2. **它是用来证明事实，还是推动动作？** 证明事实的风险低，推动动作（"点链接注册/下载/领模板"）的风险高。

据此，CiteDuo 的 GitHub 地址**只在结尾的利益相关声明里出现一次**，不写成 CTA。更保守的做法是连网址也去掉，只留仓库名（"搜得到"）。

联系方式（含谐音、拼音、数字、符号间隔等变体）以及二维码，在正文、评论区、头像、封面、个人简介里都属于高风险。曾有营销博客称「个人简介是唯一安全引流位」，**未找到官方依据，按传闻对待**。

### 1.3 不要把同一个回答复制到多个问题下

官方明文禁止，多个创作者的经验贴也都指向「复制粘贴后立刻被限制」。想覆盖多个问题，就针对每个问题各写一遍，别复制。

同样被反作弊（瓦力）盯上的还有：新账号短时间内密集回答、停留时间异常。

## 2. 打法

| 维度 | 结论 |
| --- | --- |
| 形式 | **回答 > 文章（专栏）> 想法**。回答自带流量池，专栏基本只靠自己的粉丝 |
| 账号 | 用已有的号，别新建。先正常回答两三个问题，建立行为轨迹 |
| 自问自答 | 不要 |
| 标题 | 不要悬念式、煽动式 |
| 利益相关 | 结尾声明一次，克制 |
| 目标 | 讲透一个问题；工具在结尾出现一次 |

**HN 要求"能直接试用"，知乎不要求。** 这条差别决定了两个平台要用两份完全不同的稿子。

## 3. 自写提纲（用你自己的话写，别勾 AI 声明）

每一节后面标的是**只有你知道的细节**——那些是别人写不出来的部分，也是这篇稿子值得存在的理由。

**① 开头（前 5 行必须完成三件事）**
问题、为什么重要、判断方向。建议从一个具体场景切入：综述里写了"B 是在 A 的基础上改进的"，被追问依据时答不上来。
> 你的细节：你自己有没有被这么问过？当时是怎么答的？

**② 先分清两个问题**
「这篇论文周围有什么」是邻域探索；「这两篇论文之间是什么关系」是关系判定。大多数工具回答的是前者，因为图上的一条边不携带理由。

**③ 核心判断 + 一个失败过程**
判断：有没有关联不是是非题，是证据分层问题。
失败过程（**这节的素材只有你有**）：你第一版把"摘要向量相似"和"B 引用了 A"画成了同一种边，只靠颜色深浅区分强弱；后来拿熟悉的一对论文一试，最短路径的中间节点跟两端只有措辞相似。
> 你的细节：当时你是先怀疑哪一步的？如果换成不熟悉的领域，你会不会被骗过去？

**④ 五层证据**（每一节都按「判断 → 为什么 → 例子 → 所以」写）
1. 直接引用（看引用出现在引言还是顺带一提；注意方向）
2. 共被引（集体判断，较可靠）
3. 文献耦合（反映阅读面，综述型论文会污染它）
4. 作者在相关工作里的并列讨论（人写的，但常是惯例式罗列，信息藏在正文）
5. 纯语义相似（最弱；用途是扩展候选，不是证明关系）
> 你的细节：这五层在你项目里的权重是多少？为什么这么排？（**记得说明这是设计选择，不是实验结论**）

**⑤ 只有一条路径时先当巧合**
图够大时几乎总能连起来，所以"找到路径"不构成证据。给一个可操作的自测：逐跳问"这一跳属于哪一层"，只要有一跳说不上来就不能写进论证。再说备选路径的价值（三条独立路径指向同一中间节点 → 稳健；只有一条 → 多半巧合）。

**⑥ 排序的边界**（这节最能体现你想清楚了）
新论文/预印本、冷门方向、跨领域、综述型论文作中间节点、引用方向。

**⑦ 工程取舍**（三段以内，别写成技术博客）
上游覆盖与限速差异（arXiv 明文 3 秒一次）；上游 429 的退避会变成用户的等待时间；字段选择比算法优化更影响体验。
> 你的细节：1.8 MB ↔ 21 KB、5.9 秒 ↔ 1.1 秒、10-15 秒 ↔ 约 1 秒，这三个数字。

**⑧ 为什么要求 AI 先检索再回答**
模型的记忆正好落在最弱那一层：会把"看起来像"当成"确实有"。

**⑨ 局限**
覆盖不均、权重是设计选择、工具只能帮你排除弱路径。

**⑩ 结尾凝练 + 利益相关**
把全文压成一句更高层的判断，然后一次克制的声明。不要 CTA。

## 4. 可用的真实细节（都是实测过的）

- 同一个查询：**10-15 秒 → 0.98-1.37 秒**（`/api/connect`，热库）。三个原因：批量请求塞了每篇最多 1000 条被引列表（实际只用前 25 条）→ 1.8 MB / 5.9 秒，改后 21 KB / 1.1 秒；约 4500 条边逐条 auto-commit，光 fsync 约 6 秒；重试退避 1.2/2.4/4.8 秒，在 429 频发时用户先干等 8.4 秒。trace 用 `CONNECT_TRACE=1` 打开。
- 证据权重：直接引用 1.0 > 引用方向 0.95 > 文献耦合 0.8 > 相关工作 0.6 > 向量相似 0.45（**设计选择**）。
- 一个曾经真实存在的 bug：批量请求没有取嵌套的 `citationCount`，"引用最多优先"的排序一直在读到 `undefined`，等于空转。可以作为"元数据字段级坑"的例子。
- 合规取舍：arXiv 条款只允许为个人使用或研究目的存储与提供 e-print，所以公开实例上默认只给摘要 + 原文链接。

## 5. 发布前检查清单

- [ ] 全文没有微信号、公众号名、二维码、邮箱、电话，也没有任何变体写法（谐音、拼音、数字间隔）
- [ ] 没有「私信领取」「加群」「点链接注册」「回复关键词」这类导流 CTA
- [ ] 唯一的外链是结尾利益相关声明里的项目地址（或干脆去掉网址只留名字）
- [ ] 头像、封面、个人简介里没有二维码或公众号露出
- [ ] 没有把同一个回答复制到第二个问题下
- [ ] 标题不是悬念式、煽动式，且与正文判断一致
- [ ] 利益相关只声明一次
- [ ] 如果用了 AI 起草：**已经勾选「包含 AI 辅助创作」**
- [ ] 上游限速、条款、平台规则这类会变的信息，标了核验日期

## 6. 时间线

知乎对账号行为敏感，所以先做铺垫，再发长文：先用一两周正常回答一些不相关的问题（真实参与，不是养号话术），再发这篇。发布后不要立刻在评论区补链接，也不要私信邀请别人看。
